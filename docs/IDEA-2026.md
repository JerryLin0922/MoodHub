# MoodHub 创意提案（2026-10）

> 本文件由 Marvis 维护会话基于 [RESEARCH-2026.md](RESEARCH-2026.md)、[FEEDBACK-2026.md](FEEDBACK-2026.md)、[FIRST-PRINCIPLES.md](FIRST-PRINCIPLES.md) 与合并后的 phase3 代码沉淀。每个创意都标注了假设、验证方式与优先级，供路线图裁剪使用。

## 背景

- 2026 行业审计显示：25 款 Android 心理健康 App **全部**内嵌未披露追踪 SDK（68% 未披露一半以上），主流 AI 陪伴 App 被 Mozilla 全线警告「Privacy Not Included」。
- MoodHub 的核心差异点已经确立：**本地优先 + 零追踪 + 可验证隐私**。创意应围绕把这一差异放大成用户可感知的体验，而非追逐云端功能堆叠。

## 创意 1：本地洞察周报（Local Insights Weekly）

**假设**：用户流失主因是「记了但没反馈」。在本地用规则 / 可选本地模型生成每周摘要，让用户感到记录有回音。

- 每周日晚生成「本周心情曲线 + 睡眠趋势 + 压力高峰时段 + 树洞主题聚类」；
- 全程本地聚合，数据不出本机；用户可一键导出为图片 / Markdown 分享；
- 若用户启用了 AI 且明确同意，可附加 AI 解读（仍只发送摘要，不发送原始记录）。

**优先级**：P0（直接增强留存）
**验证**：周报分享率 / 用户回访率对比开启前后 4 周。

## 创意 2：情绪花园 2.0（游戏化最小闭环）

**假设**：FEEDBACK-2026 中「日记太干」是最高频痛点；游戏化能显著降低连续记录门槛。

- 按日记记录频率生长植物：连续记录 streak 解锁新形态，心情均值影响花园配色；
- 花园纯本地生成，无服务器、无排行榜（避免社交压力与隐私风险）；
- 与现有 streak / 成就规划合并实现，控制为「一次渲染层改动 + 两条数据字段」。

**优先级**：P1（已有 FEEDBACK 支撑）
**验证**：连续 7 天记录率、streak 中断后回访率。

## 创意 3：E2EE 可选同步（用户自持数据副本）

**假设**：一部分用户需要「多设备」，但拒绝云厂商读取数据。给一个中间解：用户自选同步介质。

- 在现有加密备份基础上，增加「增量 .enc 同步到 WebDAV / 本地文件夹 / 网盘目录」；
- 口令不出本机，服务端 / 网盘侧只持有密文；恢复时支持合并（按日期 upsert）；
- 实现上复用 `crypto.ts` 的 PBKDF2-SHA256 + AES-256-GCM，工作量集中在同步状态机。

**优先级**：P2（依赖 P1 稳定后）
**验证**：多设备用户占比、同步冲突率。

## 创意 4：危机后关怀（Follow-up 回访）

**假设**：规则引擎已能识别危机信号（`rule.crisis`），但一次求助卡片之后缺少「后续回访」，关怀链断裂。

- 危机识别后 24h / 72h / 7d 生成本地回访提醒：「上次你说不太好，现在感觉如何？」；
- 全部本地触发，不回传任何数据；用户可一键关闭；
- 与休息提醒共用提醒基础设施。

**优先级**：P1（安全价值高、成本低）
**验证**：危机用户 72h 内回访完成率、用户反馈。

## 创意 5：数据互通（导入导出生态）

**假设**：健康数据的价值在于能进能出；降低迁移成本是获客手段。

- 双向互通：Daylio（心情 CSV）、Apple Health / Garmin（睡眠与心率）、WHOOP / Oura（HRV、静息心率）；
- 统一映射层放在 `src/core/`，新增来源只需加一个适配器；
- 导出保留全部字段并带版本头，保证未来可无损迁移回 MoodHub。

**优先级**：P2
**验证**：导入转化率（导入后 7 天留存 vs 未导入）。

## 实施建议

1. 按 P0 → P1 顺序落地：先做**本地洞察周报**与**危机后关怀**（纯本地、成本低、直接服务用户价值）；
2. **情绪花园 2.0** 与 FEEDBACK 中的游戏化规划合并成一次版本迭代，避免重复开发；
3. 每个创意都遵循「本地优先」铁律：不引入账号、遥测与第三方 SDK；需要联网的能力一律默认关闭、显式开启。
